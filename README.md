# Feedgarden

Feedgarden collects developer and AI sources into local SQLite and publishes a bilingual chronological feed. Each item has its own Markdown page, source tag, 1–3 topic tags, and a clickable original URL. The English site is at `/feedgarden/`, with Simplified Chinese at `/feedgarden/zh-CN/`.

Use Node 24–26 for the runner (`npm ci`), Node 26 and Ruby 4.0.6 for the pinned Jekyll Obsidian theme. X setup (`npm run setup:twitter`) also requires `uv`. The local DSH dependency is pinned to `0.1.7-rc.2`. Its model is `deepseek/deepseek-flash`, with effort `off`. Configure `DEEPSEEK_API_KEY` in local DSH credentials, or set `FEEDGARDEN_AGENT_API_KEY` / `DEEPSEEK_API_KEY`. Keys stay out of Git and generated content.

On Windows, install the shared toolchains globally. Use Node 26 for both projects, RubyInstaller **Ruby+Devkit 4.0.6**, Bundler 4.0.16, Git and uv. Open a new PowerShell after installation so it receives the updated PATH. RubyInstaller's MSYS2 toolchain supplies native gem builds. Keep `node_modules` and the patched X CLI environment local because their versions and authentication behavior belong to this project.

```powershell
winget install --id RubyInstallerTeam.RubyWithDevKit.4.0 --exact --version 4.0.6-1
gem install bundler -v 4.0.16 --no-document
npm ci
npm run setup:twitter
npm run feedgarden -- doctor

npm run site:serve
```

The preview is at `http://127.0.0.1:4174/feedgarden/` (Chinese: `/feedgarden/zh-CN/`). `doctor` does not call the model or collect live data. Summarization needs the DeepSeek credential above; authenticated X collection additionally needs `TWITTER_AUTH_TOKEN` and `TWITTER_CT0` in the runner environment. A new empty database does not contain the checked-in article history: do not run `render` merely to preview existing content. Windows flushes file contents before atomic replacement, but Node cannot fsync the parent directory there; directory-entry crash durability remains a POSIX-only guarantee. Generated schedulers still target Linux/WSL.

All commands, including `migrate` and `rollback`, discover `feedgarden.jsonc` or `feedgarden.json` in the working directory. If both exist, pass `--config FILE` explicitly. 所有命令均支持自动发现 JSONC 或 JSON 配置；两者同时存在时须用 `--config FILE` 指定。

`migrate` is required for an existing schema 2 database. It makes a permanent online SQLite backup, preserving WAL data, reports, original configuration, dependency/theme locks, code revision and checksums under `.local/migrations/`. It then freezes the migration calendar day's **Asia/Shanghai midnight as one instant**, excludes every existing `(source,id)`, resets collection cursors, upgrades additively, and replaces the public report tree with item content. Old report URLs return 404. Existing items are retained privately and are not backfilled. Migration and content replacement use recoverable journals. Migration archives are excluded from normal backup retention.

For local rollback, stop the scheduler and runners, then run `feedgarden rollback ARCHIVE`. The command verifies archive checksums, preserves the new database/content, retires WAL/SHM after closing SQLite, restores the old data/configuration/reports, and clears the lease only in the restored copy. Continue with the recorded old code revision in an independent worktree. A remote rollback requires an ordinary Git revert and Pages rebuild.

Configuration v2 uses `feed.directory`, `feed.topics` and `collection.backfillDays`. `collection.enrichmentRefreshDays` defaults to 7 (0–30), measured from each item’s first observation. Sources retain their streams and ordered fallback channels. A valid empty response stops fallback; unavailable or stale channels permit the next channel. A successful collection round sets the stream cadence. After a failed round, each enabled channel keeps its own retry time, so a failed fallback cannot postpone a due primary. Sources collected in one run share host pacing and robots policy. `source.agent` overrides model/effort. arXiv `includeKeywords` retains lexical relevance filtering; X reposts are excluded. There is no report frequency or seal period; daily selection is optional per source. GitHub collection remains disabled; its stored historical data and adapter remain available.

Feed and X CLI channels keep valid entries when individual rows are malformed, mark coverage partial and record the skipped count. An entirely malformed nonempty response fails, allowing fallback; a valid empty response still stops fallback. arXiv pages remain strict so a bad entry cannot advance their pagination checkpoint. RSS/Atom 和 X CLI 会保留有效条目，并记录无效条数及覆盖不完整状态；全部条目无效时尝试备用渠道，有效空响应则停止回退。arXiv 保持整页校验，避免跳过错误条目后推进分页断点。

Channel kinds select collection transports. Source-specific enrichment, filtering and summary contracts use the built-in source IDs `hackernews`, `producthunt`, `openai`, `anthropic`, `arxiv` and `x`. Keep those IDs when changing their channels; use `name` to change their displayed labels. Custom source IDs use generic collection and summary behavior, so an `hn-api` channel alone does not enable the Hacker News article/discussion contract.

Product Hunt includes the current source-local day as a provisional snapshot. Long ranges fetch at most seven daily pages per run and retain a checkpoint with the original range and next date; subsequent runs resume it, while an explicit `--since` restarts the range. A failed daily leaderboard does not prevent collecting later days within that batch; when every requested day fails, the next channel can run. A unique native Post ID from the captured page aligns leaderboard and Atom identities for the same launch date. Cards without that evidence retain their route identity.

During summary preparation, Product Hunt items also check their own Product Hunt product/post page for an explicitly associated repository. The product's `githubUrl` (or a repository used as its primary website) becomes optional `repo_url` frontmatter in both languages. Profiles, comment links and recommended products are excluded. Product pages, including results with no repository, are cached for six hours; `summarize --source producthunt --refresh` checks the source again and reuses unchanged summaries. `--rebuild` also regenerates summaries. A transient page failure retains an already verified repository for the same product route. Repository-only updates reuse the accepted summaries and item paths without another model call. Captured responses, the last successful repository check timestamp (repositoryCheckedAt), and the last network attempt timestamp (repositoryLastAttemptAt) remain in the local database. Cache hits do not count as network attempts.

Hacker News summary preparation also retrieves the linked public HTML/text article and a bounded discussion sample. Mozilla Readability extracts article prose without executing scripts or loading page resources. Short originals (up to 600 characters) render as verbatim excerpts of at most 25 words/240 characters; substantial originals receive a bilingual article summary. Discussions receive their own bilingual synopsis, selected comment links and a full-thread link (`discussion_url` in frontmatter). Article facts and commenter opinions remain separate. Article pages cache for six hours; HN story/comments cache for one hour. A failed refresh retains previously accepted evidence for the same article and original feed text. PDF/media-only pages and inaccessible originals retain the supplied post text and available discussion.

HN comments follow the API's ranked display order, with up to six valid top-level comments from eight candidates and one contextual reply for each of up to four threads. Deleted/dead comments and mismatched parents are excluded; selection is bounded and does not imply consensus. The [official HN API](https://github.com/HackerNews/API) supplies display rank but no individual comment score. Linked article requests bind a validated public IP to each direct connection or proxy CONNECT, including robots and redirect requests. Host, TLS identity verification and NO_PROXY matching retain the original domain. IPv6 endpoints must be global unicast, excluding reserved identifiers, documentation and IPv4 tunneling ranges. Requests respect robots rules and never crawl onward from article/comment links. Public-only fetching supports direct connections and HTTP(S) proxies; unsupported proxy transports fail closed. Local DNS must supply trustworthy, reachable addresses; a proxy cannot silently replace them with its own DNS answers, and failed connections never fall back to an unpinned hostname. Captured source responses remain in SQLite. The trusted `hackernews.md` skill extension and discussion text participate in the HN summary cache key; other sources keep their existing skill identity.

A persistent indexed queue prepares newly collected or changed items. Observation timestamps alone do not enqueue unchanged facts; metrics, corrected dates, URLs and content changes do. Recent enriched items refresh at their source’s cache interval until the first-observation window closes. Older unchanged items with accepted summaries remain stored and stop automatic network refreshes; changed source facts and unfinished revisions still require preparation. `summarize --source ID --refresh` explicitly refreshes historical evidence; `--rebuild` also regenerates its summaries. Parsed article/repository results, including missing articles, are reused while the response bytes stay the same. Configuration or skill changes can require a full planning pass, but only re-enqueue recent items or unfinished summaries. A zero-day window disables periodic refreshes without preventing initial processing.

Eligible new items enter the summary queue, FIFO per source and round-robin across sources. Sources with `selection` queue only their selected items. Dated items must meet the cutoff instant. Explicit offsets are honored; date-only and unzoned ISO/SQL dates use the source timezone (Shanghai by default, Los Angeles for Product Hunt). Undated items use their stable first observation and display “First observed”; a sample feed's generated timestamp is not a publication date.

Reddit and Hacker News each publish at most 50 items per Shanghai publication day. Their optional `source.selection` specifies `method`, `dailyLimit` (default 50) and `updateDays` (default 7, including today). HN uses `0.75 * ln(1 + max(score, 0)) + 0.25 * ln(1 + max(comments, 0))`, without age decay; unavailable counters remain unknown. Reddit collects each community's weekly `top.rss?t=week&limit=100` and scores its original position `r` in an `N`-entry sample as `100 * (N-r+1)/N`. All communities compete for the same daily 50 places. This is relative RSS sample popularity, not measured votes or a complete community percentile. Ordinary `new` feed order is never used as heat. Scored items come first; unknown Reddit rankings fill remaining places by newest publication. Equal scores use newest publication, then native ID ascending. Earlier days freeze after leaving the update window. Raw candidates, observations, ranking evidence and accepted copies remain private; dropped items stop enrichment and new ACP calls, and returning items reuse accepted copies and stable path numbers. A failed request preserves its last valid ranking; rate-limit cooldowns are retained for subsequent ranking commands.

Reddit 和 Hacker News 按北京时间发布日各输出最多 50 条，Reddit 多个社区合并竞争名额。HN 使用赞分与评论数的加权对数；Reddit 使用周榜 RSS 在各社区返回样本内的相对名次，不新增 OAuth，也不把 `new` RSS 顺序当成热度。含当天的近 7 个日期随采集重排，更早日期固定。未知 Reddit 排名按发布时间从新到旧补齐，同分按发布时间和原生 ID 稳定排序。全部候选、证据及已有摘要保留在私有数据库，落选条目不再触发正文补取或新的摘要调用。

The seven-day update window means seven Shanghai calendar dates including today, rather than a rolling 168 hours. Newly discovered posts dated before that window stay private until an explicit `rank --history --source ID`, even if a weekly RSS sample still includes them. For example, at October 13 00:01 in Shanghai the active dates are October 7–13; a post from October 6 00:02 remains private although it is less than 168 hours old. Existing historical selections stay frozen.

七日更新窗口指含当天的七个北京时间日期，并非滚动 168 小时。新发现但发布日期早于窗口的帖子保留在私有数据库，须显式执行 `rank --history --source ID` 才能参与历史入选，即使周榜 RSS 仍包含它。例如北京时间 10 月 13 日 00:01 的活动日期为 10 月 7–13 日；10 月 6 日 00:02 的帖子虽未满 168 小时，仍只保留私有候选。已有历史入选集合保持冻结。

Ordinary selection reads the active source-local dates through indexed UTC instants in pages of 128 records; queued date corrections also revisit affected identities. Historical ranking deliberately visits older records. HN fetches up to eight stories concurrently and commits each batch's evidence, selection scores and native metrics together, with an unexpired-lease check at the transaction boundary. Older cached observations cannot overwrite newer metrics or revive a more recent dead/deleted state. Historical Reddit feeds update only posts assigned to the requested week/month/year/all window. A valid empty RSS ranking leaves posts unscored and uses the chronological fallback; malformed or failed responses defer the day. Private exclusion markers apply to imported archives as well as generated summaries. Materialized daily selections preserve frozen days and the previous selection during failures; sorting the latest scores at render time would lose those guarantees.

普通重排通过索引按来源时区的活动日期读取，每页 128 条，并处理队列中的日期更正；历史重筛才遍历旧记录。HN 最多并发获取 8 条，每批的证据、评分和原始指标在同一事务提交，提交前检查租约仍有效。旧缓存不会覆盖更新的指标或恢复已确认的死亡／删除状态。Reddit 周／月／年／总榜仅更新属于该窗口的帖子。有效空榜保留“排名未知”并按时间补齐；响应无效或请求失败则保留旧入选集合。显式私有排除标记也适用于导入归档。每日入选集合持久保存，以维持历史冻结和失败时保留旧集合的行为。

```sh
npm run feedgarden -- rank --history --dry-run
npm run feedgarden -- rank --history
npm run feedgarden -- rank --history --source hackernews
```

`rank` refreshes ranking evidence for the active date window; `--history` also reselects older archives. `--dry-run` uses an isolated temporary database and leaves the real database, queues, locks and content unchanged. Reports include candidate counts, unknown rankings, scoring method, kept IDs and deferred days. Before the first archive import, a database and content backup is saved below `.local/ranking-backups/` (or the configured storage directory). Existing bilingual bodies and numbers are imported without regeneration, and other source files remain byte-for-byte intact. Historical Reddit IDs are matched against week/month/year/all RSS for dates less than 7/30/365 days old or older, respectively; unmatched IDs remain unknown. HN stories explicitly marked dead/deleted by the official API are excluded while their private copies remain stored. Fetch failures defer the affected day rather than deleting its archive. Historical scores describe currently available evidence, not the original day's heat. Applying a rank command renders both languages locally and does not publish. Deferred days produce exit code 1 and can be retried after their cooldown.

历史重筛先备份数据库和完整归档，复用已有双语正文并保留编号；其他来源文件保持原字节。Reddit 按历史日期匹配周／月／年／总榜，未匹配条目标记排名未知，按时间补齐。HN 官方明确标记为 dead／deleted 的帖子退出候选，私有副本继续保留；请求失败则保留该日原有归档，稍后重试。历史评分使用当前可获取的数据，无法还原发布当天的真实热度。`--dry-run` 不修改真实数据库、队列、锁或归档；应用重筛只更新本地双语输出，不自动发布。

The local `2026-10-09` reranking keeps 50 of 329 Reddit candidates and 50 of 129 HN candidates. Removing 358 items means 716 bilingual output files are removed; their original bodies and candidates remain private. SQLite is the runner's durable source for candidates, evidence, selection and archive bodies, and is intentionally gitignored. Keep its online backups and `.local/ranking-backups/` outside the repository as well. A fresh database can import the surviving `content/` files and render them again, but recovering dropped candidates requires the private database backup or the original files from Git history. The published static site can still build from tracked `content/` without SQLite. Run commands from the repository root; relative feed, topic and locale paths use that working directory.

本地对 `2026-10-09` 重筛后，Reddit 从 329 条、HN 从 129 条各保留 50 条，共移除 358 条的 716 个双语输出文件；原始正文和候选保留在私有归档中。SQLite 是采集、证据、入选集合和归档正文的持久数据来源，按设计不进入 Git。除仓库内备份外，也应另存数据库在线备份和 `.local/ranking-backups/`。空数据库可重新导入剩余 `content/` 并渲染；恢复落选候选需要私有数据库备份或 Git 历史中的原文件。已发布的静态站点仍可仅从 Git 中的 `content/` 构建。命令从仓库根目录运行，相对的正文、主题和语言配置路径按该工作目录解析。

Scheduled `run --due` performs collect → rank → summarize → render → backup before optional publication. The ranking pass also runs when collection is not yet due, using the existing evidence cache and cooldowns, so HN RSS candidates missing API counters can recover automatically. Missing HN counters still defer their day and preserve its last valid selection; the runner prints ranking diagnostics and records a partial run with exit code 1. Archived bodies are reused by default, including for selected items. Explicit `summarize --source hackernews --refresh` or `--rebuild` allows selected archived items to be enriched and regenerated; those generated summaries then follow the normal periodic enrichment schedule, while dropped items remain private. Already completed artifacts for subsequently dropped items finish their jobs and retain reusable private copies.

定时 `run --due` 按采集→评分→摘要→渲染→备份执行，再按配置发布。即使采集尚未到期也会运行评分，复用现有证据缓存和退避状态，让 HN RSS 中缺少互动数的候选在 API 恢复后自动入选。指标缺失期间保留该日上一份有效入选集合，并输出评分诊断、记录 partial 状态及退出码 1。已有归档默认复用正文，入选条目也一样；显式使用 `summarize --source hackernews --refresh` 或 `--rebuild` 才允许补取并重新生成入选归档，生成后的摘要恢复正常的周期补取。落选条目继续私下保留，已完成但随后落选的摘要也会完成任务状态并保存为可复用的私有副本。

Malformed bilingual archive pairs are preserved as opaque bytes and recorded in `gaps` under channel `archive`; only their platform/date's ranking is deferred. Other collection and summary work continues. Fix both visible files, then run `archives update PATH` to validate and save that pair, followed by `rank --history --source ID` to retry. Updates keep the native identity, date and file number. `archives remove PATH` removes both outputs of a platform pair through private exclusion, or removes an opaque file from the render snapshot. It retains platform archive rows; opaque-file originals remain in the maintenance backup. Both commands save the database and complete content tree first, print the backup path, and render locally without publishing. Files already replaced by generated summaries use `summarize --refresh` for updates. To undo maintenance, restore the printed private backup with runners stopped; merely editing or deleting rendered files is overwritten on the next render.

双语归档有缺失或身份、日期不一致时，原字节继续保留，并以 `archive` 通道记入 `gaps`；仅暂停对应平台／日期的评分，其他采集和摘要继续运行。修好两份输出后，用 `archives update PATH` 校验并保存，再通过 `rank --history --source ID` 重试；更新不允许改变原生 ID、日期或文件编号。`archives remove PATH` 会私下排除平台条目的两个语言版本，或从渲染快照移除其他归档文件。平台归档记录仍保留，其他文件的原始副本保存在维护备份中。两个命令均先备份数据库和完整正文目录，显示备份路径，随后仅在本地渲染。已被摘要替换的文件使用 `summarize --refresh` 更新。撤销维护时应停下运行器后恢复显示的私有备份；直接修改或删除渲染文件会在下次渲染时被覆盖。

```sh
npm run feedgarden -- archives update hackernews/2026-10/09/item-1.md
npm run feedgarden -- archives remove other/draft.md
```

Archive import runs once per database, including when adopting an earlier directory-based import marker. Changing `feed.directory` changes the publication destination and reuses private snapshots, selections and exclusions; it does not import that directory over the database or create another import backup. Use the explicit archive maintenance commands for revisions. Malformed YAML or media URLs leave the complete affected Markdown file unchanged and do not stop other files from rendering. Archive paths must stay inside the output directory; Unicode, spaces and dots in ordinary filenames remain supported.

归档按数据库首次导入一次，并兼容旧版按目录保存的成功标记。修改 `feed.directory` 只改变发布位置，继续复用私有快照、入选集合和排除状态，不会将新目录重新覆盖导入或额外创建导入备份；修订正文应使用显式归档维护命令。YAML 或媒体 URL 异常时，该 Markdown 文件完整保留原字节，其他文件继续渲染。归档路径须位于输出目录内，普通文件名仍支持中文、空格和点号。

Dry-run isolation copies the complete SQLite database and may read/import the complete content tree into its temporary workspace. Archive import stages immutable bytes in a temporary SQLite snapshot, keeping file/identity metadata and the file or bilingual pair being processed in JavaScript memory. Temporary disk use and elapsed time still scale with the archive size. The validated snapshot enters the private database in one transaction after the backup; failed imports roll back and remove their temporary snapshot. Archive identities and reserved-number conflicts are checked before the first import backup, and backup and commit retain their lease checks.

`--dry-run` 会复制完整 SQLite 数据库，并可能在临时工作区读取／导入完整归档。归档导入将不可变字节暂存到临时 SQLite 快照，JavaScript 内存仅保留文件／身份元数据和正在处理的文件或双语文件对；临时磁盘使用量与耗时仍随归档总量增长。通过校验的快照在备份后以单个事务写入私有数据库，失败时回滚并清理临时快照。导入前先检查归档身份与编号预留冲突，再创建备份；备份和提交仍检查租约。

Archive maintenance scans only the requested file or bilingual pair once initial import is complete. Unrelated edited files cannot block that update. Rendering still publishes a complete staged tree atomically; unchanged renders skip it, while a changed render copies every retained opaque asset. Configuration changes regenerate the two locale manifests and keep all other archive bytes.

完成首次导入后，归档维护只扫描指定文件或双语文件对，其他文件的编辑不会阻断该更新。渲染仍以完整暂存目录进行原子发布；内容未变时跳过，发生变化时复制全部保留的其他归档文件。配置变化会重新生成两份语言清单，并保留其他归档字节。

Ranking updates use their evidence timestamp and must not be older than the stored ranking, item observation, embedded ranking, or HN inactive check. Older cached evidence is ignored. Selection policy revisions change deliberately when scoring/grouping/tie rules change; frozen days keep their recorded policy until historical reranking.

评分更新采用证据时间，不得早于已保存评分、条目观察、条目内评分或 HN 下架检查的任一时间；旧缓存证据会被忽略。评分、日期分组或同分排序规则变化时需要更新选取策略 revision；冻结日期保留原策略，直到显式历史重评。

The runner measures topic-registry overhead before preparing items and warns when it reaches 80% of the input budget. A registry that cannot fit stops with measured limits and guidance to shorten descriptions through `topics apply` while preserving IDs and aliases. An individual item that cannot fit is marked failed without spending an ACP attempt; following items continue. Adjust `agent.maxInputChars` or `agent.maxItemChars`, then use `--retry-failed`.

Round-robin batches contain one source. A batch contains at most 10 items (two for HN's combined bilingual article/discussion output), 4,000 normalized body characters each, and 24,000 characters for the complete JSON input including the topic registry. The default budget is 80 ACP attempts per UTC day, including failed/repair attempts (reset at Shanghai 08:00). Attempts time out after 300 seconds. One immediate artifact repair is allowed per visit; other retries back off from 15 minutes to six hours, up to five attempts per content version. Credential problems stop with a manual-action message; three consecutive runtime failures stop the run. Quota deferral leaves pending tasks and exits successfully. Other task failures produce a partial run and exit 1.

```sh
npm run feedgarden -- summarize --retry-failed
npm run feedgarden -- summarize --source openai --refresh
npm run feedgarden -- summarize --source openai --rebuild
npm run feedgarden -- doctor
npm run feedgarden -- backup
```

Identity remains `(source,native ID)`; native IDs never become path components. Content lives in `content/<source>/<YYYY-MM>/<DD>/item-<num>.md`, with matching paths below `content/_translations/zh-CN/`. The date uses the source timezone and the item's publication date, or its stable first observation when undated. Numbers start at 1 for each source/day and are reserved in SQLite, so later arrivals and repeated renders do not renumber existing items. Correcting an item's date moves it into the appropriate day, reserving a number there; previous reservations are retained and never reused. A failed render keeps its reservations and reuses them on retry; numbers remain stable but are not guaranteed to be gap-free. Frontmatter includes `date`, `updated`, `first_seen`, `date_basis`, `source_url`, and tags `source/<id>` plus `topics/<id>`. The indexed publication date follows source corrections; opening an existing database reconciles old stale index values once, preserving first observations and version history. Summaries are cached by normalized input, source identity, model/effort, skill hash and contract version. Media candidates are part of the input cache identity. Metrics, URL and date changes update presentation without regenerating text. Cached summaries are revalidated against the current fixed input. Invalid JSON or deprecated topic assignments evict the cached copy and enter normal generation, quota and retry handling. Cache eviction itself spends no ACP attempt. Failed revisions retain the last accepted bilingual snapshot. No new item is published with only one language.

Substantial articles are summarized in 2–5 short paragraphs, aiming for 150–300 English words and 450–900 Chinese characters, with optional bullet lists and a 4,000-character limit per language. Brief sources remain brief; title-only inputs retain empty summaries. RSS full content is preferred over its description. Before summarizing eligible OpenAI/Anthropic items, the runner tries the official article with robots rules, conditional HTTP caching and a six-hour freshness window. Failed article requests fall back to the feed or retain previously accepted article evidence when the feed text is unchanged. Article-fetch evidence is private and does not change collection coverage or publication dates. Sources other than HN and these official articles use supplied feed content without crawling arbitrary discovery URLs.

The runner extracts up to six source image, video, audio or PDF candidates; the agent may select up to three useful figures, recordings, documents or demos by their fixed IDs. Publishing is disabled automatically by default. The remote theme lock must match the locally trusted repository and full SHA before topic/content changes or validation. Theme builds use an environment allowlist, excluding provider/Git tokens, proxy variables and injected runtime options; Git fetch/push retain the caller’s credentials. This environment boundary is not an operating-system sandbox. `publish` fetches the configured branch into an isolated worktree, merges topic registries with a three-way base, validates the site, commits only `content/` and `config/topics.json`, and pushes without force. Legacy `reports/` deletions are permitted only with the migration journal. Independent topic additions merge; conflicting IDs stop the entire publication and preserve local data, with `.local/publish-conflict.json` for resolution. Integrate the code/theme change into the publication branch before publishing item content. To resolve a registry conflict, fetch and merge the recorded versions, then run `topics apply FILE --remote-base <recorded-remote-SHA>`, render, and retry.

SQLite retains raw responses, content versions, observations, collection cursors, gaps, summary jobs, accepted snapshots, fixed task inputs, ACP usage and run state. Future raw captures deduplicate identical source/stream/channel/URL, body, status and header snapshots, retaining their first capture; latest HTTP cache timestamps and collection/run records track subsequent activity. Existing captures and observations are not automatically deleted. Every collection retains its observations, including metric changes, so database size grows with collection activity. The `gaps` and `runs` tables support manual audit in a SQLite reader; they are not public site content.

New runner-owned task directories have `agent.workspaceRetentionDays` retention (default 7 days from creation; 0 disables cleanup). At summary startup, aged accepted, failed, interrupted and deferred directories are removed only when their ownership marker matches the database batch. Deferred batches are never resumed; their pending jobs enter a new batch on a later run. Active/prepared batches, unmarked historical directories, symlinks and paths outside the configured runtime directory remain untouched. Fixed inputs, accepted snapshots and ACP accounting remain in SQLite; database history is not pruned or vacuumed automatically. Historical report tables remain private for audit. A filesystem lock and renewable database lease prevent concurrent runners. Online backups retain seven daily and four weekly copies; private raw data, credentials and scratch workspaces are never deployed.

工作目录清理现在也包含因配额延期的旧批次；仅清理超过保留期且归属标记匹配的目录，待处理任务与数据库证据保留。数据库观察记录按每次采集留存，体积会持续增长；本项目不自动删除或去重这些审计历史。

Rate limits honor a valid `Retry-After` first. Otherwise, GitHub reset values and contemporary epoch-sized `x-ratelimit-reset` values are treated as timestamps; smaller values (including Reddit's remaining seconds) are treated as durations. Invalid values, including unsupported millisecond epochs, fall back to 30 minutes, and cooldowns are bounded to 1 second–24 hours. 限流优先采用有效的 `Retry-After`，否则区分重置时间戳与剩余秒数；无效值（包括不支持的毫秒时间戳）回退为 30 分钟，等待时间限制为 1 秒至 24 小时。

HTTP responses are limited to 12 MB of decoded bytes while reading, and oversized streams are cancelled. Article response buffers are released after their evidence is stored. Summary planning and site rendering read 128 records at a time; quota checks use an indexed timestamp. Pending batches walk an index ordered by source, first observation and item ID, skipping retries that are not yet due without sorting the whole queue for each batch. Runs with no changed or due items skip preparation and job writes. Rendering skips an unchanged tree using a content revision and fingerprints of topics, sources and locale configuration; explicit `render` rebuilds the tree and repairs missing or edited files. Changed renders still build a full tree, parse each accepted item once, and retain the recovery journal. Migration checksums stream files while preserving existing archive hashes. ACP usage and tool notification logs each retain at most 64 KiB and 128 entries, with omitted counts in the audit; complete fixed inputs and accepted snapshots remain in SQLite, while on-disk task artifacts follow the workspace retention policy.

Losing either runner lock cancels active collection/ACP work and prevents accepting new results. Database lease ownership and expiry are checked again at collection, summary, content replacement and publication boundaries; an expired lease cannot be renewed by its former owner. Saved artifacts remain recoverable. Generated schedulers have no whole-run time limit that conflicts with the daily ACP budget; individual HTTP/ACP timeouts and concurrent-run exclusion still apply. Updating an installed scheduler requires regenerating its files and reloading the service or reimporting the Windows task.
