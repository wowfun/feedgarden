Writ 此前因向 Claude Code 提供相关规则的检索引擎而被分享，此次更新加入了强制约束与持久化记忆。作者现在把它描述为一个本地治理、上下文与连续性运行时。其架构是 Claude Code 钩子连接到一个本地 Python 守护进程，由它管理检索与工作流状态，并用 Neo4j 存储知识与决策记录。它需要 Python 3.11+ 和 Docker。

在 Work 模式下，实现写入之前有两道验收门禁：先是通过的计划，再是通过的测试骨架。钩子会检查试图进行的写入，包括受支持的 shell 写入方式；如果缺少审批，写入会被拒绝。审批来自用户手动输入的回复，并使用一次性令牌，因此智能体不能仅靠声称已获批准来推进门禁。此外还有对计划漂移、项目边界、凭据路径的检查，以及在 Debug 模式下先有已记录的根因、再修改源码的要求。作者指出一个重要局限：测试骨架门禁只检查是否存在合格的测试，并不能证明断言写得好或实现正确。

持久化记忆可跨会话保存项目记忆与决策溯源，包括已批准的计划、约束规则 ID、变更文件、提交记录以及变更背后的理由，这样后续会话就能了解某个方案为何被选中，而不必从当前代码去推测意图。

检索层会根据当前任务、文件、工具和工作流阶段提供相关规则、方法论和既往决策。作者总结的主要设计经验是：把工作流权威保留在代码中，用检索为 Claude 提供在该工作流内工作所需的信息；检索到某条指令并不自动使其成为被强制执行的硬性要求。作者希望已经在使用钩子或持久化记忆的人提供反馈。
