一位此前只用 Claude Code 做过个人项目的 Reddit 用户，即将首次把它用于大型专业项目。以往他的用法主要是写提示词、让模型实现。此次工作包含规模较大的后端，之后还有前端；由于这是真正的商业应用，他希望尽量减少缺陷、避免架构失误，并在项目增长过程中保持代码库可维护。

帖子向有经验的用户征求实用经验，而不是神奇提示词或完全自动化的方案。其问题包括：

- 工作流如何组织，是否要走规格、计划、实现、测试的流程
- 如何管理 CLAUDE.md 和项目文档，使其不至于过于庞大、难以维护
- 哪些做法有助于尽早发现错误、防止 Claude 破坏既有功能
- 自定义技能、子智能体、hooks 或其他工具中哪些真正有效
- 在大型项目上犯过的最大错误是什么，如果重来会如何改进

其目标是一套可靠的开发流程：既让开发者保持掌控，又充分发挥 Claude Code 的作用。帖子没有给出答案、结果或建议，只是征求建议和资源。
