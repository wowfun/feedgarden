Agent memory lets LLM agents reuse past experience without updating their parameters. The authors note that semantic similarity alone does not guarantee that a memory will be useful: downstream performance depends on how memories are selected and presented, not only on how closely they match the query.

They propose MemComposer, a memory composer that jointly examines the current query and retrieved candidates to decide which experiences to include, how many to select and how to order them. It is trained with Experience Policy Optimization &#40;ExPO&#41;, a GRPO-based framework that evaluates assembled memory contexts through complete agent interactions and uses task-success feedback to optimize the assembly policy rather than ranking only by similarity.

Across three τ²-bench domains with two frozen executors, MemComposer beat the strongest baseline for each executor while reducing average memory-token usage by 16.9% and 4.9%, respectively, according to the authors. Performance rose while average memory-token use fell, so the gains did not come from adding more memory text. The learned policy also transferred to unseen domains, executors and memory banks, and benefited from memories generated by stronger models without further training. The results indicate that query-specific memory assembly can be learned from downstream task feedback.
