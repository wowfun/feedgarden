## HN discussion

Based on 10 selected comments and replies.

Commenters note the patch series carried a commit message stating that the code, the test programs, the review behind the listed changes and the first draft of the text were produced with an LLM coding assistant &#40;Claude Code&#41; under the author's direction, while the measurements were run on his own machine.

Several commenters frame the news as less surprising than it looks. One argues Torvalds long ago shifted toward reviewing and managing the codebase rather than writing kernel code himself, though he likely still codes personal projects. Another observes the diffs are moderately sized and readable, unlike the multi-thousand-line commits people often produce with LLMs.

A recurring theme is process rather than tools. One commenter says patches reaching Linux are normally filtered through maintainers and subsystem heads first. Another cites Torvalds's patch-acceptance policy: code must still be audited by a maintainer, and because machine-written code cannot be copyrighted it cannot be Open Source, so it must be substantially human-produced to enter the kernel. A further commenter separates using AI from misusing it — generating code and reviewing it manually is defensible, while shipping a superficially reviewed program as one's own is not.
