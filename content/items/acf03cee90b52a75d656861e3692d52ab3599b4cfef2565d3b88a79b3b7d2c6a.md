A developer describes running a custom "code factory" harness with up to four agents writing code at once, alongside parallel deep-research sessions with ChatGPT on topics they think of. They dump every idea into the code factory immediately so it can be examined and implemented later, work on non-overlapping parts of an app such as client and server at the same time, and try not to hesitate when a new idea or bug appears.

They say they cannot go faster this way. Doing HTML artifacts to prototype UI quickly means they can no longer steer the harness in VS Code, and doing research or learning takes time away from directing the agents, yet coding blindly without checking produces "slop" and an app that is not what they want.

They also note a sequencing problem: sometimes a future bug can only be fixed after a previous task finishes, and a feature may only make sense once the developer has prior context. The post ends with open questions rather than answers: how people manage 24/7 coding with multiple 20x plans and ten agents at once, and how anyone can know what to build as if they knew every bug to fix and every feature to add. The author is /u/pizzae.
