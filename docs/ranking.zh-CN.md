# 每日排名

## 候选筛选与已发布内容

Reddit 和 Hacker News 分别按上海时区的发表日期筛选每日 Top50，用于决定哪些候选进入正文提取、补充信息和摘要生成。`source.selection` 的 `dailyLimit` 默认为 50，`updateDays` 默认为包含今天在内的 7 个自然日。

已经进入发布目录的 item 会保留中英文文章页。后续跌出 Top50、历史重排，或 HN 官方 API 将原始条目标记为 dead/deleted，都不会自动删除已发布文章。随着新的候选入选，同一天累计发布的条数可以超过 50。通过归档维护显式删除或排除的内容仍不会输出。

未发布且落选的候选停止补充信息和新的 Agent 调用；已经完成但尚未发布的摘要保存在私有数据库中，重新入选时可以复用。排名状态和已发布记录分开保存。升级已有数据库时，只将当前发布目录中的中英文文件对登记为已发布，不会自动公开更早转入私有归档的内容。

## 排序规则

HN 使用 `0.75 * ln(1 + max(score, 0)) + 0.25 * ln(1 + max(comments, 0))`，不做时间衰减，缺失指标保留为未知。Reddit 根据各社区每周 `top.rss?t=week&limit=100` 样本中的原始位置 `r` 和样本数 `N` 计算 `100 * (N-r+1)/N`，合并后竞争同一天的 50 个候选名额。这是 RSS 样本内的相对热度，并非真实票数或完整社区百分位。

已知分数优先；Reddit 的未知分数按发表时间从新到旧补足。分数相同时依次按发表时间从新到旧、原始 ID 升序排列。超出更新窗口的日期冻结；请求失败或限流时保留此前有效排名，延后受影响日期的筛选。

## 命令与恢复

```sh
npm run feedgarden -- rank
npm run feedgarden -- rank --history --dry-run
npm run feedgarden -- rank --history --source hackernews
```

`rank` 更新最近窗口内的候选排名，`--history` 包含更早日期；两者都保留已发布内容。`--dry-run` 使用隔离数据库，不修改真实数据库、队列、锁或内容。普通排名命令会在本地重新渲染中英文内容，不部署网站。报告中的 kept IDs 是当前入选候选，不代表完整已发布列表。

首次导入已有文章前，会在 `.local/ranking-backups/`（或配置的存储目录下）保存数据库和完整内容备份。SQLite 持久保存候选、排名证据、已发布记录和归档正文，请保留其在线备份。发布记录随内容目录替换的恢复流程提交，中断后不会丢失已经落地的文章，也不会将放弃的暂存内容误记为已发布。数据库丢失时可从现有 `content/` 重新导入已发布文件；私有候选需要数据库备份恢复。
